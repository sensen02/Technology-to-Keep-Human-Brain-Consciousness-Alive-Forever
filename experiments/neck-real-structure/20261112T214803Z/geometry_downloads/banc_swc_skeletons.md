# banc_swc_skeletons.zip

## Purpose

Per-neuron skeleton files for the BANC connectome, in standard
SWC format. Two resolutions, both included in the archive:

- `<root_id>_l2.swc` — L2-resolution skeletons at the chunked-graph
  L2 level (the FlyWire `pcg_skel` default). Compact, fast to load,
  the canonical resolution for downstream natverse analyses.
- `<root_id>_skeleton.swc` — full-resolution skeletons (one node per
  reconstructed branch point). Larger; appropriate when geometric
  precision matters.

The root_ids in the archive include both v888 root IDs (the print
materialization and version of record in the paper) AND v626 root IDs
(the preprint materialization). Users coming from preprint-era
analyses can therefore find skeletons keyed to the same IDs they
already have; users on v888 should prefer those. Cross-reference via
the `root_626` and `root_888` columns of `banc_888_meta.feather` when
needed.

These skeletons are the morphological substrate behind every BANC-side
NBLAST score in the dataset and behind the cable-length numbers in
`banc_888_metrics.feather`. They are also the natural input for any
user-side morphology analysis or visualization.

## Provenance

Generated by **bancpipeline**, by two different routines — one per
resolution:

- `<root_id>_l2.swc` — L2 chunked-graph skeletons from FlyWire's
  `pcg_skel` (https://github.com/CAVEconnectome/pcg_skel), acquired in
  `banc/metrics/banc-l2.R` via `bancr::banc_read_l2skel()` and rerooted
  to the nucleus.
- `<root_id>_skeleton.swc` — full-resolution skeletons from `skeletor`
  (https://github.com/navis-org/skeletor), computed in
  `banc/metrics/banc-calculate-skeletons.R` via `fafbseg::skeletor()`
  (`method = "wavefront"`, healed, rerooted to the soma by density,
  resampled to 1000 nm node spacing) over the segmentation mesh;
  proofread neurons only.

The export step (`banc/share/banc-export-skeletons.R`) writes
`<root_id>_skeleton.swc` where a full-resolution skeleton exists and
falls back to `<root_id>_l2.swc` otherwise, one file per neuron in SWC
format. The ZIP archive is packaged from the source GCS directory at
upload time.

## Schema

Standard SWC format. Each row is one skeleton node:

```
PointNo Label X Y Z Radius Parent
```

with whitespace separators and `#` comments at the top. Node
coordinates are in **nanometres** (BANC space) — not voxels. Nodes carry `Label = 2`
(SWC's "axon" code) by default rather than a real compartment
assignment — true axon/dendrite splits live in
`banc_888_edgelist_split_v2.feather`, not in the SWC.

## Usage

In R via natverse:

```r
library(nat)
n <- read.neuron("720575941521131930_l2.swc")
plot3d(n)
```

In Python via navis:

```python
import navis
n = navis.read_swc("720575941521131930_l2.swc")
n.plot3d()
```

For a single neuron without downloading the ZIP, bancr's wrapper
`banc_skeleton(id)` fetches the SWC over the network.

## Related files

- `banc_888_meta.feather` — resolves each root ID to identity and
  annotations.
- `banc_888_metrics.feather` — pre-computed cable length, surface area
  and node count for each skeleton.
- `banc_neuron_meshes.zip` — full segmentation meshes for the same
  segments when higher-resolution morphology is needed.
- NBLAST feathers under `nblast/` (e.g. `banc_fafb_783_nblast.feather`)
  — pairwise morphology similarity derived from these skeletons.

## Notes

- **Two skeleton sets exist on GCS, don't confuse them.** This ZIP is
  the dual-suffix set under `compiled_data/banc_888/banc_banc_space_swc/`
  (`_skeleton` = skeletor high-res where available, else `_l2` = pcg_skel).
  A separate bulk `neuron_skeletons.zip` at the bucket root is the
  pcg_skel/L2 set only.
- The ZIP file is large. Stream-decompress if disk space is tight
  (`unzip -p` to stdout into a per-file consumer).
- Coverage is broad: an SWC exists for every BANC segment with an L2
  graph at v888, including small fragments and glia. For a clean
  proofread set, filter against `banc_888_meta.feather`
  (`proofread == TRUE` and `super_class != "glia"`) before processing.
- For the highest-resolution morphology, work from the segmentation
  meshes (`banc_neuron_meshes.zip`) instead. The L2 skeletons trade
  some detail for tractability.
