# 复杂移动冻结基线检查表

- 范围为人工搭建大脑项目 P1、P2、S2、S4、S5。所有组起于同一路径及哈希的标称站姿，71 网格、18 足垫、42 路有界 PD。本轮没有训练更新、附着、外力或回合内重置。视景经真实渲染发布，身体侧只消费颈后指令。定速组使用 DNg97 工程信号，仅用于同几何的身体能力判断。
- 场景与主要判据先写入 SCENES.json，评估输入封存于 BASELINE_INPUTS.sha256。目标为有色视觉标记，箱和坑用实体 MuJoCo 模型，原生求解力监测箱触及坑底。轨迹以及 71 网格及 18 足垫范围以 20 ms 间隔保存，末状态必存。非足地面力按 Core 的 1 ms 状态读出，末窗用原站稳检查。窄坑和宽坑与平地对照的站姿和图像目标相同，坑沿为实体接缝。相机中坑场的地面材质也变化，因而采用无图像的定速组来区分身体层影响。
- 每个完整回合保存 RESULT.json、TRACE.npz、TRANSPORT.json、RUN_IDENTITY.json 与 shell 日志及退出码。源身份、权重和相关工件在进入各回合以及退出后核验。进程退出成功与各项任务门独立。
- 环境沿用 20261110T125712Z 的 Python 3.12、MuJoCo 3.9、Torch 2.5.1 CPU，EGL 以及单线程 OMP／OpenBLAS／MKL。源码路径与帧文件在各条记录中。
- 首批 ./drive.sh evaluate.py <场景> <策略> <输出> --preview 暴露导入路径、身份文件重名和子目录未建立，失败均保留对应日志及首状态工件。修复后窄坑和偏置单箱两个编译、冻结站姿和真实眼图预检成功，初始观察最大偏差均为零。预检身体 Bench 的初始化积分与后续报告的正式原生时钟分开。
- python3 -u run_suite.py 用五进程上限跑 SCENES 的全部组合。./drive.sh optics_audit.py 使用六份旧平地归档姿态作眼图诊断，无正式控制回合。首个批量诊断错误地让逐帧视觉 API 只读批首，保留原记录后改为逐帧调用。
