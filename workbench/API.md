# Workbench P2 backend contract

Hand-built engineering prototype, not validated hardware/biology. No live acquisition, DAQ, new recording physics or P4. Existing `serve_workbench.py --port 8766` entry point remains; binds only 127.0.0.1. Importing the module does not create output directories or start workers.

## HTTP

All routes require Host `127.0.0.1:<port>` or `localhost:<port>`; supplied Origin must exactly equal `http://<Host>` (GET and POST). No CORS. POST requires application/json, one Content-Length, no Transfer-Encoding, <=2 MiB, strict JSON object (duplicate keys, NaN/Infinity and overflowing numbers rejected). Body reads time out after 10 seconds. Responses have no-store and nosniff. Static files use the previous exact allowlist plus **only** `/modules/data.js`, `/modules/timeline.js`, `/modules/transforms.js`, `/modules/service.js`, `/modules/inspection.js`, `/modules/navigation.js`, `/modules/layers.js`. Resolved paths must remain inside viewer; no raw data.js, directory listings or project root exposure.

| Method/path | Contract |
| --- | --- |
| GET /api/status | Legacy service/mode/job/bench fields, plus api_version, queue count/cap and recovery_warning. `job` is latest **submitted** job, not necessarily the executing job. |
| GET /api/manifest | Versioned cached snapshot metadata; see below. |
| GET /api/datasets/{name}?snapshot={hash} | Raw cached section object, no wrapper; fixed body/neural/electrodes/calcium/bench whitelist. Copies only requested section. Unknown/unavailable section 404; optional snapshot hash mismatch 409: discard partially loaded sections and reload manifest. Bench section is original snapshot evidence/chain, not current evaluated bench status; overlay /api/status.bench while retaining chain. |
| GET /api/data | Legacy full viewer JSON shape; bench report replaced by current server-evaluated report while preserving original chain. Deep copy avoids mutations contaminating cache. |
| GET /api/jobs | `{jobs:[...],latest_id,max_pending,recovery_warning}` in submission order. Poll this to reconnect to all queued/running jobs. |
| POST /api/jobs/recording | `{}` or `{idempotency_key:"client-generated-key"}`; fixed parameters, 202 new, 200 idempotent replay, 409 duplicate active unkeyed request or full queue. Returns full job plus duplicate boolean. |
| GET /api/jobs/{id} | Job state, input_hash, run_id, timestamps, limits, errors, last 4000 log bytes; 404 unknown. |
| POST /api/jobs/{id}/cancel | `{}`; queued -> cancelled, running -> cancelling -> cancelled. Repeated/terminal cancel is harmless 200 and never rewrites an already completed job. |
| GET /api/jobs/{id}/result | Validated immutable report belonging to this id; 409 unless completed; 503 if stored artifact fails schema/hash/identity revalidation. |
| GET /api/recording | Last **submitted** run's report only if completed and validated. Otherwise status/run_id/job_state/result_available:false/previous_run_id/stale_result, **no old bands/budget fields**. No implicit fallback to global legacy recording output. |
| POST /api/bench/evaluate | Exactly config object + csv string; real existing bench.evaluate checks. INVALID_INPUT -> 400 and does not replace prior bench report; other statuses -> 200, atomic latest publication. Uploaded report-only objects rejected. |

## Jobs, duplicates, restart and artifacts

One serial dispatcher, up to four waiting jobs plus one executing. Submission hashes recording script plus electrode engine sources; execution rejects a queued run if its source changed. Dispatcher/publication/persistence failures expose `worker_error` and `healthy:false` on status and reject further submissions instead of silently leaving a dead worker accepting work. Optional idempotency keys are 1–128 chars; replay of a key returns that same persisted job even after completion/restart and does not change latest_id. Distinct keys explicitly enqueue distinct fixed recording runs. Unkeyed `{}` submission gets 409 while another unkeyed recording is queued/running/cancelling, and creates a new run once the previous one is terminal. No client-supplied simulation parameters, shell commands or output paths.

States: queued, running, cancelling, completed, failed, cancelled, timed_out, interrupted. All queue/state writes are atomic rename + file/directory fsync. State lock prevents two new servers owning the same output store. On restart queued jobs resume in original order; running/cancelling jobs become interrupted, never auto-retried or relabeled completed. Broken queue JSON/schema is preserved as jobs.corrupt-<id>.json with a warning, not silently accepted. Completed reports remain accessible by id and are revalidated on every read. Logs and terminal history are retained; operators must manage long-term disk retention (pending queue bounded, archive history not capped).

Production worker has 2 GiB address-space limit, common BLAS/OpenMP thread environment=1, 120 s wall timeout, 32 MiB individual-file limit. Linux parent-death guard kills the child if service crashes; cancel/timeout kills and reaps the process group. No multithreaded preexec_fn. Existing recording script is loaded without main execution, then its main function's OUT global is set to the unique run folder before calling main. Existing outputs/embodied_body/electrode_recording.json/png are never copied, overwritten or promoted. Publication requires zero exit status and a fresh <=16 MiB JSON report with strict numbers, recording_only, fixed 7um/20um geometry, 30000 Hz sampling, three band budgets with V²/uV consistency, alias/baseband sum consistency, nonempty consistent acceptance checks. Server stamps run_id, schema_version, units, validation marker and hash. A failed/cancelled job never publishes a result. A completed older queued run remains inspectable by id but is not shown as the latest request's result.

Artifacts: outputs/workbench/jobs.json; runs/<id>/worker.log; runs/<id>/electrode_recording.json/png (raw diagnostics); runs/<id>/result.json (validated atomic publication); bench/<id>/{config.json,measurements.csv,result.json}; bench_latest.json. Only controlled API reports/log tails are served, not arbitrary artifact paths.

## Manifest

`schema_version: workbench-manifest-1`, dataset_id viewer-replay, source_id viewer/data.js, raw-file source_hash SHA256, run_id snapshot-<first16hash>, mode, clock_policy, datasets array. Each section body/neural/electrodes/calcium/bench has dataset_id/source_id/run_id, canonical section source_hash, origin provenance, kind simulation/illustration/measurement, available/availability, units `{position,value,time}`, coordinate_frame, data_url `/api/datasets/<name>?snapshot=<raw-file-source-hash>` and data_key. Top-level manifest.meta preserves the snapshot's original metadata. Clock contains clock_id `<section>-independent`, unit s, original times_s, frame_count, origin_s, synchronized false. These are snapshot identifiers, **not claims of original simulation-run identity**. Bench kind describes intended evidence category, not measurement availability or a pass claim. Unknown source units remain null.

The data.js parse/hash cache invalidates on mtime_ns, size or inode change. Manifest-first loading supports independently requested dataset sections (geometry and associated frames together); a section read deep-copies only that section. This is section-granularity loading, **not per-frame streaming**, range pagination or SSE. Full data JSON remains available for compatibility. Frontend polls jobs; independent source seconds must not be presented as physically synchronized merely because normalized playback is linked.

## Lightweight verification

`python3 -m unittest test_workbench_backend -v` uses temporary directories, ephemeral loopback ports and tiny fake workers only. It tests atomic-failure preservation, parse caching, independent clocks, queue bounds/order, duplicate replay, cancel, timeout, failed/missing/corrupt/tampered results, stale-result suppression, restart, corrupt-state quarantine, single-owner locking, bench validation, reconnect routes and Host/Origin/body/static restrictions. The real production launcher is additionally exercised with a tiny replacement script asserting resource/thread limits and isolated output. No real scientific benchmark or 8766 restart is performed by these tests; parent/integrator must separately run the bounded real diagnostic and integrated UI acceptance.
